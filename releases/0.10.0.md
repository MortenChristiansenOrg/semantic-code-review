# v0.10.0 — 2026-10-30

## Overview

Agents can now show that a feature works, not just say so. Evidence such as screenshots, recordings and captured output appears in the viewer, so you can inspect it without checking out the branch. You can also keep track of which insights you have read.

Versions beginning with zero remain experimental: any release, including a patch, may contain breaking changes.

## Breaking changes

- **Stages now require an `evidence` list.** An implementation started on an earlier version fails validation after updating. Finish or archive it first, or add `"evidence": []` to each file in `.semantic-review/stages/` and `.semantic-review/.work/stages/`.
- **Earlier versions can't read artifacts from this version.** Stage files with evidence are rejected by versions before 0.10.0. Keep using 0.10.0 or newer for those implementations.
- **Agents are now expected to capture evidence.** The skill asks for evidence for each user-observable feature or acceptance criterion, or a stated reason when there is none. A missing reason produces a warning and does not block anything.

## Improvements

- **Evidence.**
  - The agent records captures with `stage evidence`. Screenshots and recordings are preferred when a change has visible output. Terminal output, HTTP exchanges, logs, output files, measurements and reports are also supported.
  - Choose **View evidence** on an evidence pill to see images, video and text, before and after comparisons, and the linked acceptance criteria and changes. You can leave a note or feedback there too.
  - Each capture records the stage head it came from. The viewer marks it **Stale** when the stage has since moved, which includes a restack.
  - Captures stay out of stage diffs, and publishing and archiving include them. Publishing makes them visible to anyone with access to the metadata branch, so the skill tells agents to check them for secrets and personal data. `stage evidence-remove` deletes a capture.
- **Mark insights as reviewed.** A round control on each insight pill marks it as reviewed, and each stage shows how many are done. If an insight changes after you marked it, the control shows **!** until you mark it again. Marks are saved locally and don't affect approvals.
- **New work starts from the latest target branch.** `/semantic-flow implement` now fetches and fast-forwards the target branch first, using the new `refresh-target` command.
- **Easier to read agent questions.** During interactive review, questions now appear in a larger, centred overlay.
- **More useful code links.** The skill now tells agents when to link an insight to specific lines, so more of them should appear beside the code they explain.

## Bug fixes

- In interactive review, a thread could be handed back as a new round while the agent's reply to it was still being saved. The wait now allows time for the reply to land, and a late reply also answers the newer round.
- `sync` could be misled by a mirror-style fetch configuration into overwriting a local branch. It now fetches into a private ref and applies only remote-tracking updates.

## Updating

Run `/semantic-flow update`, or download `semantic-flow-0.10.0.zip` and its `.sha256` checksum, verify them, and install the complete extracted `semantic-flow` folder.

Node.js 20 or newer and Git remain required for the CLI and viewer. Windows, macOS, and Linux are supported. The implementation and feedback formats remain experimental `0.1` and changed in place; there is no automatic migration, so see Breaking changes above for active implementations.

## Known issues

- A restack marks evidence stale even when the behavior didn't change. Recapture it only if the behavior could have changed.
- Evidence files are limited to 25 MiB each and 100 MiB per stage.
- Evidence is recorded per stage. There is no redaction tool and no evidence kind for preview links. See issue #135.

# v0.3.0 — 2026-09-12

## Overview

Keep multiple reviews available, attach files to messages, and compare changed files with their last approved state. Review data now lives in a user folder, making it independent of browser storage limits and easier to inspect and clean up.

Versions beginning with zero remain experimental: any release may contain breaking changes.

## Breaking changes

- Review progress, drafts, personal notes, preferences, and feedback now live under `~/.semantic-flow/reviews/`. Browser data and worktree-local `.semantic-review-feedback/` directories are not imported or used as a fallback. Finish existing reviews with v0.2.0 before updating, or retain that installation and its data if you need to return to them.
- The experimental feedback `0.1` format now supports managed file attachments and messages containing only attachments. Older tooling cannot process this context reliably. Use v0.3.0 for both the viewer and feedback commands; integrations should resolve `feedbackDirectory` through `semantic-flow inspect --json` instead of constructing the old path.
- File approvals now belong to each change node's use of a file. A shared file must be reviewed separately in each node.

## Improvements

- Switch between saved reviews from the Reviews picker without issuing another review command. Reviews in different repositories and worktrees remain available together, and commands such as Prepare comments run in the selected review's worktree.
- Save review state independently of browser ports and share it between the viewer and CLI. Independent edits from concurrent tabs merge; conflicting edits show an error instead of silently overwriting each other.
- Find review data in readable folders named after the worktree and implementation, with a full hash suffix to preserve uniqueness. Set an absolute `SEMANTIC_FLOW_HOME` to choose another data root.
- Mark reviews complete, reopen them, delete their local data, or clean unused attachments and snapshots. Deletion previews explain what will be removed and preserve repository files and implementation artifacts. Unused-file cleanup protects referenced files and gives recent uploads and snapshots a one-hour grace period.
- See changes since the last file approval when that approval becomes stale. Retained snapshots survive restacking and Git garbage collection; switch back to the stage diff to add line comments.
- Attach images and other local files to messages, personal notes, and replies by choosing files, dropping them onto the text field, or pasting images. Each message supports ten files of up to 20 MiB each. Agents can access submitted attachments through feedback commands.

## Bug fixes

- Review controls preserve open file views, editor focus, and draft text during approvals and attachment changes, avoiding disruptive redraws.
- The Reviews picker overlays and blocks the page while open, with smooth opening and closing. File highlights, comment toggles, and Add note footers remain consistent after interactions.
- Concurrent review writes and deletion reject stale sessions, preventing old tabs from recreating deleted data. Interrupted deletion can be retried from the picker.

## Updating

Run `/semantic-flow update` to install this release, or download `semantic-flow-0.3.0.zip` and its `.sha256` checksum, verify them, and install the complete extracted `semantic-flow` folder. Node.js 20 or newer and Git are still required; Windows, macOS, and Linux are supported.

Read the breaking changes before updating active reviews. There is no migration or backward-compatibility layer. The updater replaces the tooling without converting existing review data, and downgrading does not undo data changes. The implementation and feedback formats remain experimental `0.1`.

## Known issues

- Moving an artifact worktree creates a new review identity. Its previous review remains listed for cleanup; data does not follow the move automatically.
- Historical approval comparisons do not support line comments. Binary files show content identities, and snapshots larger than 20 MiB report that content comparison is unavailable.

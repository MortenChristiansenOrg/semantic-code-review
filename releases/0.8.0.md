# v0.8.0 — 2026-09-29

## Overview

Insights and validation evidence can now link directly to committed code, with the full explanation and surrounding code shown together in the viewer. File approvals and line feedback drafts also survive restacks when the reviewed file has not changed.

Versions beginning with zero remain experimental: any release, including a patch, may contain breaking changes.

## Breaking changes

None. Existing artifacts remain valid, and code links are optional.

## Improvements

- Attach a line or span of committed code to any insight or validation record. Links can be added while recording an item, or attached, retargeted, and removed later with `stage target` without replacing its text.
- Open linked insights from their reasoning, file, or line in the viewer. The dialog shows the full explanation beside highlighted code and surrounding context, with separate scrolling for each pane.
- Unchanged code links can follow line shifts and file renames. Edited, missing, or ambiguous targets show **Needs review** and preserve their original code context. Automatic mapping does not imply that the reasoning has been reviewed again.

## Bug fixes

- File approvals no longer become stale solely because a restack changes commit IDs. Content, path, file mode, classification, and ownership changes still invalidate approval. Base-change notices compare the file itself rather than the base commit ID.
- Line feedback drafts remain attached to their lines and export successfully after a restack when the file diff is unchanged. Existing drafts recover their file identity from the saved Git snapshots; changed files or unavailable history remain stale.
- Failed feedback exports now show the reason each note was skipped, including when no notes could be exported.
- Clicking outside file search closes the dialog and restores focus. Reopening search starts the result list at the top.

## Updating

Run `/semantic-flow update`, or download `semantic-flow-0.8.0.zip` and its `.sha256` checksum, verify them, and install the complete extracted `semantic-flow` folder. Node.js 20 or newer and Git remain required for the CLI and Viewer; Windows, macOS, and Linux are supported.

The implementation and feedback formats remain experimental `0.1`; no data migration is required. Use this release or newer tooling when sharing artifacts that contain the new optional code links. Existing approvals for executable files or other non-default Git file modes may need one re-approval. If an older line draft's original Git snapshots are unavailable, review its text and create a new note on the current diff before sending it.

If upgrading from before v0.5.0, also read the intervening releases' breaking changes before continuing existing reviews.

# v0.5.0 — 2026-09-22

## Overview

Review remote branches privately, report problems from the main skill, and write comments without distracting save indicators. This release also makes failed review cleanup easier to diagnose and retry.

Versions beginning with zero remain experimental: any release may contain breaking changes.

## Breaking changes

- The separate `semantic-flow-report` and `semantic-flow-repair` skills are no longer distributed. Use `/semantic-flow report` followed by a description of the problem instead; the report workflow also handles requests for a local fix. After installing the complete updated main skill, remove obsolete standalone skill installations if you have them. Updating the main skill does not remove those separate folders automatically.

## Improvements

- Use `/semantic-flow review --branch <branch-name>` to review a remote branch in an isolated local clone, with private notes and approvals. Published Semantic Flow metadata supplies the stages and change nodes when available; otherwise, stages follow the branch's first-parent commits. Remote reviews support personal review only, without author feedback threads.
- Refresh a saved remote review with **Refresh branch**. File comparisons retain the last saved approval across force pushes and renames; historical approvals remain available even when commits leave the branch.
- Files that appear in several stages compare against the previous stage that changed that file, including across renames, so intervening stages do not obscure the relevant changes.
- Report problems through the main skill even when the CLI or Node.js is unavailable. The workflow gathers diagnostics, prepares a reviewable report, and can investigate a local source fix when requested.

## Bug fixes

- Personal notes, feedback, replies, and comment edits now save after a short typing pause. Routine save indicators are hidden, while failures remain visible. Finishing an earlier save no longer bypasses the delay for newer edits.
- Failed review cleanup identifies the affected paths and includes file-holding process information when the platform can provide it. Retry details survive reopening the Viewer, including failures that leave unreadable review data behind.
- Cleanup lock recovery no longer reports a stale lock owner's process after successfully recovering that lock.

## Updating

Run `/semantic-flow update`, or download `semantic-flow-0.5.0.zip` and its `.sha256` checksum, verify them, and install the complete extracted `semantic-flow` folder. Node.js 20 or newer and Git remain required for the CLI and Viewer; Windows, macOS, and Linux are supported.

The implementation and feedback formats remain experimental `0.1`. This release introduces no format migration. If upgrading from before v0.4.0, also read the intervening releases' breaking changes before continuing existing reviews.

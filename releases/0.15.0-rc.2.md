# v0.15.0-rc.2 — 2026-11-23

## Overview

This is the second prerelease of 0.15.0. It is less tested than a normal release and is published so that it can be tried before everyone gets it. Plain `/semantic-flow update` does not install it; `/semantic-flow update -p` does. These notes describe what changed since 0.15.0-rc.1. The notes of [0.15.0-rc.1](https://github.com/MortenChristiansenOrg/semantic-code-review/releases/tag/v0.15.0-rc.1) describe what changed since 0.14.0.

This prerelease fixes most of the known issues of 0.15.0-rc.1:

- An agent whose feedback round a second agent took over can no longer change the stages or answer for that round.
- Notes on removed lines of renamed files can be sent and stay on their line.
- The viewer shows the same files, renames and diffs as the stage inventory, whatever your Git configuration.

The viewer also shows each agent reply as its own notification, stays still when the agent replies, and approves large groups of files much faster.

Versions beginning with zero remain experimental: any release, including a patch, may contain breaking changes.

## Breaking changes

- **A listening agent names its round.** While a listening agent answers a round, `implementation` commands that change the implementation must pass the round's claim with `--claim`. `feedback agent progress` and `feedback agent ask` need it whenever an agent listens. The claim is the one the feedback preflight or wait returns, which replies already use. The skill does this. Outside a listening round, changes without a claim work as before. Scripts of your own that change the implementation while an agent listens need the option.
- **Batch input takes a plain array.** In JSON input, `items`, `threads` and `replies` take an array of objects. An array that holds the batch as JSON text, such as `"items": ["[...]"]`, is refused.
- **Stage diffs no longer follow your Git configuration.** The viewer, remote reviews and `stage plan --selectors` now list and show the files, change kinds and renames of the stage inventory whatever the Git configuration. The viewer's diffs and hunk selectors no longer follow `diff.algorithm`, `diff.indentHeuristic`, `diff.interHunkContext` or text conversion (`textconv`). Hunk selectors and line ranges recorded under such settings may need to be generated again with `stage plan --selectors`, and the stage organized again: until then the stage fails validation, which also stops the next feedback round. A line thread written on lines those settings placed elsewhere may show as stale or, for a text conversion, on another line. With Git's default settings nothing changes.
- **A removed line of a renamed file is named by the file's new path.** `feedback thread add` refuses the old path of a renamed file and names the path to use. Threads already stored under the old path keep their meaning while their stage head has not moved, and are saved with the new path the next time they change. If the head has already moved, they stay at file level.

## Improvements

- **One notification per agent reply.** Each reply that arrives while the viewer is open gets its own notification in the bottom left corner. It names what the thread is about and shows the reply's first line. **Show** opens the thread and scrolls to the reply. More than five notifications collapse into one group, and **Dismiss all** clears them. A notification goes away once you read its reply anywhere. The generic "Review updated" notice is gone.
- **The viewer stays still when the agent replies.** A reply in a thread above what you are reading no longer pushes the page or an open diff down.
- **Approving a group of files is much faster.** "Approve all files in a group" sends up to 200 files in one request instead of one request per file. A group of 300 files took over 20 seconds and now takes about one second. A file that cannot be approved fails alone and shows its own error.
- **Clearer CLI errors.** A wrong command or input says what is wrong and what is valid. Unknown keys in JSON input are named with their location and the valid keys. Wrong values list the allowed ones. `--help` works for every command, also outside a Git repository, and `help <group> <command>` works too. JSON input may start with a UTF-8 byte order mark, as Windows PowerShell 5.1 writes it.

## Bug fixes

- **Two agents on one review.** When a second agent started listening while the first was in the middle of a round, both could change the same stages. Now the CLI refuses the replaced round's stage changes, restacks, replies, progress notes and questions, and the skill tells that agent to stop. The new agent gets the threads at once. This was a known issue of 0.15.0-rc.1.
- **Work left by an earlier round.** When an agent started listening while a stage branch held a commit that no restack recorded, or while a restack was stopped at a conflict, its first wait failed and nobody listened. Now the new agent takes the work over: it records the commits or completes the restack, and then answers the threads. It keeps the commits, which may be your own changes, and asks in the viewer about uncommitted edits.
- **Removed lines of renamed files.** A note on a removed line of a file that the stage renames could not be sent, and an existing thread on such a line moved to file level once the stage head changed. Now the note can be sent. After a correction or restack, the thread follows its line while the stage still renames the file from the same path and its diff still removes that unchanged line. This was a known issue of 0.15.0-rc.1.
- **A renamed file compared with the wrong file.** When a stage between the one that changed a file and the one that renamed it added or deleted a similar file, the viewer could compare the renamed file with that other file, and refused every line note on it. Now each file is compared over its own stage's diff, as the stage inventory pairs it. Approvals of a file that was compared with the wrong file show as changed.
- **Diffs that differed from the inventory.** With settings such as `diff.ignoreSubmodules`, a low `diff.renameLimit` or `diff.noprefix`, the viewer, remote reviews and selectors could show other files or renames than the stage inventory, or fail to match hunks. A `diff.orderFile` that named a missing file made the viewer's diff fail. Changed lines starting with `-- ` or `++ `, such as SQL comments, were dropped from small stages' diffs. Landing detection missed squash merges under a custom `diff.context`, and approval comparisons hid changes of line endings only under `core.autocrlf`. All of this now works. This was a known issue of 0.15.0-rc.1.
- **Cleaning unused files.** Cleaning a review's unused files could remove an attachment that a submitted thread still used. Cleanup now reads all feedback the way the viewer does. It is disabled, with the reason, while some of it cannot be read or is behind a symbolic link or junction. Deleting the whole review still works. This was a known issue of 0.15.0-rc.1.
- **Keyboard focus under the top bar.** Moving focus with Tab could scroll the focused element under the viewer's top bar. It now stops below the bar and below the notes panel's filter. The fresh-link notice no longer covers the top bar and side panels. This was a known issue of 0.15.0-rc.1.

## Updating

From 0.15.0-rc.1, update between feedback rounds: let the listening agent finish its round and stop it, run `/semantic-flow update -p`, then run `/semantic-flow review` again. An agent that keeps listening with the old skill does not pass the claims this version requires. Implementations in progress continue across the update.

From 0.14.0 or older, first read the [0.15.0-rc.1 notes](https://github.com/MortenChristiansenOrg/semantic-code-review/releases/tag/v0.15.0-rc.1): their breaking changes apply, and implementations in progress cannot continue across the update. Then follow the steps under Updating there, with `semantic-flow-0.15.0-rc.2.zip` and `semantic-flow-0.15.0-rc.2.zip.sha256` from this release. Their updater cannot install a prerelease, so the skill folder is replaced once by hand. [Installing and updating](https://github.com/MortenChristiansenOrg/semantic-code-review/blob/master/docs/releases.md#installing-and-updating) describes each step.

`/semantic-flow update -p` (or `--prerelease`) installs the newest version including prereleases, which are less tested than normal releases. The option applies to that run only. Plain `/semantic-flow update` stays on normal releases: on a prerelease it changes nothing until a normal release of the same version or newer exists, and then installs it.

Viewer pages that are open during an update need a fresh link afterwards: run `/semantic-flow review` again.

Node.js 22 or newer and Git are required for the CLI and viewer. Windows, macOS and Linux are supported.

The implementation and feedback formats remain experimental `0.1` and changed in place. A line target names the file by its path in the stage on both sides of the diff, and hunk selectors refer to a diff made with Git's default settings. `docs/artifact-format.md` and `docs/feedback-format.md` describe the formats.

## Known issues

- **Attributes can still change a stage's inventory and diffs.** Attributes in the repository's `info/attributes` file, and with Git older than 2.41 also `.gitattributes` in the checkout, can still change what a stage's inventory lists and how its files are compared. They now apply the same way everywhere. This will not be fixed ([#236](https://github.com/MortenChristiansenOrg/semantic-code-review/issues/236)).
- **A commit at the moment of a takeover.** If a second agent takes a round over between the first agent's last check and its `git commit`, that commit can still land on a stage branch. The restack that would record it is refused, and the new agent takes it over as leftover work.

# v0.14.0 — 2026-11-17

## Overview

Evidence no longer turns "stale" after every restack, and stages with large changes now restack reliably. Bug reports are created when you ask for them, without a prescribed confirmation step.

Versions beginning with zero remain experimental: any release, including a patch, may contain breaking changes.

## Breaking changes

- **Evidence no longer records the stage head it was captured from.** The `headRevision` field is removed from evidence entries in the implementation format, which stays experimental `0.1` and changed in place. An implementation whose evidence still has `headRevision` now fails validation, and every command on it stops. Finish or archive active work before updating, or keep 0.13.0 for it. To continue such an implementation with 0.14.0, delete the `headRevision` line from each evidence entry in its stage files.

## Improvements

- **No more stale Evidence.** Evidence used to be flagged stale whenever its stage head moved, which every restack did, so the flag was mostly noise. The viewer now always shows **View evidence** with the capture time, and `stage plan`, `stage finish` and `validate` no longer warn about it. The agent still recaptures or removes evidence when review feedback changes the behavior it shows.
- **Reports are submitted when you ask.** `/semantic-flow report` no longer saves a draft file and asks you to confirm the exact title, body and account before posting. When you ask for an issue, the agent creates it. Your own instructions and your harness's permissions decide whether you review it first. Sanitizing private details, duplicate checks and the rule against blind retries stay the same.

## Bug fixes

- **Large stages restack.** Restacking, `sync` and the automatic restack in `feedback` failed on a stage whose patch was larger than 1 MB, with an error that gave no reason. Git output can now be up to about 512 MB. When a Git command does fail, the error now says why, for example that its output was too large.

## Updating

Run `/semantic-flow update`, or download `semantic-flow-0.14.0.zip` and its `.sha256` checksum, verify them, and install the complete extracted `semantic-flow` folder.

Node.js 20 or newer and Git remain required for the CLI and viewer. Windows, macOS, and Linux are supported. The implementation format remains experimental `0.1`, with the evidence change above. The feedback format did not change.

## Known issues

- **Very long tooltips can't be scrolled with the keyboard.** If a stage explanation is taller than the window, keyboard-only users see only the part that fits. Screen readers still read all of it. Tracked in [#143](https://github.com/MortenChristiansenOrg/semantic-code-review/issues/143).

# v0.2.0 — 2026-09-09

## Overview

Semantic Flow now comes as a ready-to-install download, with readable release notes and updates from GitHub releases. Specifications can link to work tracked by any provider.

This is the first packaged release. The skill includes the stage-based workflow, command-line tools, schemas, and local review viewer. Versions beginning with zero remain experimental: any release may contain breaking changes.

## Breaking changes

- Updating now installs a published release. Contributors who want to build from their own checkout must pass `--source /path/to/semantic-code-review`; `--use-current-source` also requires that explicit source path.
- Old browser settings from earlier experimental viewers are no longer converted. Old single-file expansion settings and approvals stored as booleans or diff fingerprints are ignored. Reopen the files you need and approve them again. Current comments, drafts, file approvals, and expansion settings remain usable.

## Improvements

- Download the built skill without cloning this repository or installing build tools. Release archives include all runtime files, source-commit information, and dependency notices.
- Update to the newest published version with `/semantic-flow update`. The updater displays release notes for versions you skipped and checks the download before replacing your installation. You can select a specific version for recovery.
- Record a specification from any tracker or other source without changing the schema. For example, `--source-kind jira --source-reference TEAM-42 --source-url https://example.com/issues/TEAM-42` is accepted. References must still be non-empty, and supplied URLs must be valid.

## Bug fixes

- The version command reports the release's original source commit even when the skill is installed inside a different Git repository.

## Updating

You need Node.js 20 or newer and Git for repository operations. Windows, macOS, and Linux are supported.

For your first installation, or to replace an older source-based installation, download `semantic-flow-0.2.0.zip` and its `.sha256` checksum from this release. Verify the checksum, extract the archive, and install its complete `semantic-flow` folder in your harness's user-level or repository-level skills directory. Keep a copy of the previous folder until the new installation works. See the [installation guide](https://github.com/MortenChristiansenOrg/semantic-code-review/blob/v0.2.0/docs/releases.md#installing-and-updating) for commands and viewer handling.

After this one-time transition, `/semantic-flow update` downloads subsequent releases directly. A matching running viewer restarts at the same URL, preserving browser drafts. Repository code, implementation artifacts, and feedback files are not changed by the updater.

The implementation and feedback formats remain experimental `0.1`. Finish or archive active work before adopting a release with incompatible format changes. Downgrading the skill does not undo data changes. The separate `semantic-flow-report` skill remains independently installed and is not included in this archive.

## Known issues

- Releases do not migrate old experimental artifact or browser-state formats. Unsupported artifact data fails validation; use the matching older skill to finish existing work when needed.

# v0.4.0 — 2026-09-17

## Overview

Review changes with more context: reasoning counts now appear on the change nodes they describe, and approving a file moves you past its open diff. This release also improves long acceptance-criterion labels, diff gaps, and the skill's handling of routine workflow recovery.

Versions beginning with zero remain experimental: any release may contain breaking changes.

## Breaking changes

- Newly initialized implementations record `skillVersion` in their manifest. Earlier releases reject this field, so use v0.4.0 or newer for the Viewer and CLI when working with these artifacts. Existing artifacts without the field remain supported and display “Unknown”; updating the tooling does not rewrite their recorded provenance. The implementation and feedback formats remain experimental `0.1`.

## Improvements

- See decisions, assumptions, risks, validation evidence, and other reasoning counts on each related change node. Zero counts are omitted. Click a count to open the node and focus its matching entries, including checks that did not pass.
- See the skill version that initialized an implementation in the Viewer header, read directly from its manifest.
- The skill now handles routine CLI corrections, restacking, and documented recovery steps without unnecessary permission questions. Questions focus on behavior, scope, or unresolved safety conditions, while existing safeguards remain in place.

## Bug fixes

- Approving an open file collapses its diff after the approval is saved. A failed approval save leaves it open, and approvals in other nodes preserve unrelated open files.
- Long acceptance-criterion identifiers wrap within their own space instead of overlapping descriptions. Narrow screens stack the identifier, description, and status.
- Diff views show counted separators between sections where unchanged lines were omitted, making gaps clear after additions, deletions, and replacements.
- GitHub release notes no longer repeat the version and date heading already represented by the release title.

## Updating

Run `/semantic-flow update`, or download `semantic-flow-0.4.0.zip` and its `.sha256` checksum, verify them, and install the complete extracted `semantic-flow` folder. Node.js 20 or newer and Git remain required; Windows, macOS, and Linux are supported.

Use the updated skill consistently for artifacts initialized with v0.4.0. No migration is needed for v0.3.0 artifacts or review data. Updating replaces the tooling without converting existing data; downgrading does not undo artifact changes. If upgrading from v0.2.0, also read the v0.3.0 breaking changes before continuing existing reviews.
